# SerenityDenver

Discord-бот семьи Serenity: контракты, явки, отчёты, расчёт выплат, заявки,
розыгрыши, дни рождения и временные голосовые комнаты. Python 3.10+,
PostgreSQL; для Railway и CI выбран Python 3.12.

## Настройки и запуск

`.env` хранится в закрытом репозитории и читается приложением из корня проекта.
Файл `.env.example` не нужен. Приоритет: **Railway Variables → `.env` → значения
по умолчанию**. Уже заданные в Railway `TOKEN` и `DATABASE_URL` перекрывают
пустые поля файла. Секреты не выводятся при проверке настроек.

```sh
python -m pip install -r requirements.txt
python -m serenity.manage check-config
python -m serenity.manage db-check
python main.py
```

`check-config` проверяет конфигурацию без сетевых подключений. `db-check`
подключается к PostgreSQL **и применяет миграции**, как и обычный запуск.
Отдельная команда миграций: `python -m serenity.manage migrate`.

При первом запуске ID каналов и ролей задаются в `.env`; списки — через запятую без повторений.
`RANK_ROLE_IDS` упорядочен от младшего ранга к старшему. `STAFF_ROLE_IDS`
определяет доступ к рассмотрению заявок, `APPLICATION_ROLE_IDS` — выдаваемые
при вступлении роли. При первом обновлённом запуске обычные настройки сохраняются в PostgreSQL.
Дальше меняйте каналы, роли, цены, сообщения, изображения, параметры выплат и напоминаний
через `/настройки`: предпросмотр → сохранение, без перезапуска. В меню также доступны
отключение функций, восстановление панелей, диагностика и история с откатом изменений.
Секреты и ID сервера остаются в окружении. Новые алгоритмы требуют разработки.
Полная инструкция: [Управление ботом](docs/manage-bot.md).

## Деплой Railway

1. Загрузите в GitHub все изменения, включая новые каталоги `serenity/`,
   `migrations/`, `.env` и удаления старых файлов в корне.
2. В сервисе бота сохраните существующие `TOKEN` и `DATABASE_URL`, указывающий
   на нужную PostgreSQL. Команда запуска в `railway.toml`: `python main.py`.
3. Перед первым обновлением сделайте резервную копию рабочей базы.
4. При старте бот проверит настройки, подключится к БД, применит миграции
   и загрузит 19 модулей. Ошибка подключения прерывает запуск и попадает в логи.
5. После подключения бот автоматически обновит команды сервера, включая `/настройки`.
   Повторная синхронизация: `!sync` (с вашим префиксом) или `@Бот sync`.
   Команда доступна администраторам, старшему составу и владельцу бота.

В Discord Developer Portal нужны Server Members Intent и Message Content
Intent. Роль бота должна находиться выше выдаваемых ролей. Боту нужны права
на чтение истории, отправку сообщений и файлов, управление ролями и комнатами;
для отказа во вступлении — исключение участника. Права на приглашения нужны
для учёта приглашённых.

Разворачивайте **один экземпляр на один сервер**: блокировка PostgreSQL
не позволяет двум новым экземплярам одновременно обрабатывать события.
Старую версию бота перед переключением нужно остановить: у неё такой защиты нет.
HTTP-сервер не запускается, поэтому HTTP healthcheck для этого worker не нужен.

## Структура

| Каталог | Назначение |
| --- | --- |
| `serenity/cogs/` | Команды и события Discord |
| `serenity/repositories/` | Запросы к PostgreSQL |
| `serenity/services/` | Расчёты, обработка заявок, восстановление состояния |
| `serenity/ui/` | Общие обработчики интерфейса и ошибок |
| `serenity/config.py` | Типизированная конфигурация |
| `serenity/database.py` | Общий пул соединений, миграции, блокировка экземпляра |
| `migrations/` | Версионированные SQL-изменения |
| `tests/` | Проверки конфигурации, логики и интеграции с БД |
| `serenity/legacy/` | Неактивные прежние интеграции Google Sheets и Flask |

Старые Google-модули автоматически не загружаются и не переносят таблицы Google
в PostgreSQL. Активные функции работают через PostgreSQL. Настройки `GOOGLE_*`
оставлены для справочных модулей.

## Хранение данных

Один пул используется всеми активными модулями. Существующие таблицы контрактов,
явок, отчётов, машин и розыгрышей сохранены. Дополнительно сохраняются:

- заявки, решения сотрудников и целевой ранг повышения;
- дни рождения, история приглашений;
- участники записей, состояние панелей, владельцы и настройки голосовых комнат;
- очередь напоминаний и уведомлений с повторными попытками;
- неизменяемый снимок недельного расчёта и ID опубликованных результатов.

Повторная обработка явки или отчёта не создаёт повторное начисление.
Целевой ранг фиксируется до изменения ролей, поэтому повтор после сбоя не даёт
ещё одно повышение. Результат розыгрыша сохраняется до уведомления победителей.
Расчёты используют `Decimal`. Файл выплат — расчёт для сотрудников;
бот не переводит деньги.

При первом запуске импортируются доступные старые записи и дни рождения из
истории Discord, ожидающие заявки на вступление/повышение/смену фамилии,
а также прежний локальный ID панели бонусов. Для нескольких старых ожидающих
заявок одного типа от одного пользователя переносится последняя; остальные
сообщения остаются для ручного разбора. Удалённую историю восстановить нельзя.
Старые ожидающие бонусные заявки и напоминания, существовавшие только в памяти
прежней версии, автоматически не восстанавливаются.

Публикации Discord и транзакции PostgreSQL не являются одной транзакцией:
при аварии точно между отправкой уведомления и записью результата возможно
повторное уведомление. Повторное начисление при этом отдельно предотвращается.
Недельный автоматический расчёт запускается по воскресеньям с 23:30 МСК;
если бот отсутствовал всё это окно, пропущенный расчёт требует ручного разбора.

## Проверки

```sh
python -m pip install -r requirements-dev.txt
ruff check serenity tests main.py
ruff format --check serenity tests main.py
python -m unittest discover -s tests -v
```

Для интеграционных тестов задайте `TEST_DATABASE_URL` на отдельную БД с именем
**`serenity_test`**. Тесты очищают её таблицы. Без этой переменной проверки БД
пропускаются. GitHub Actions поднимает отдельную PostgreSQL 17 и выполняет
весь набор автоматически. Discord в тестах не подключается.

Прямые зависимости описаны в `requirements.in`, версии всех зависимостей
зафиксированы в `requirements.txt`; аналогично для разработки. Обновлять
lock-файлы следует вместе с проверками на поддерживаемой версии Python.

## Миграции, резервные копии и восстановление

Применённые SQL-файлы не редактируйте: бот проверяет их SHA-256 в
`schema_migrations`. Добавляйте новый файл с очередным номером. Миграции
выполняются в транзакции с блокировкой; ошибка откатывает применение.

Перед изменением схемы сохраните резервную копию PostgreSQL средствами хостинга
или `pg_dump --format=custom`. Храните копию вне контейнера приложения.
Проверяйте восстановление через `pg_restore` в отдельную пустую базу, затем
выполняйте `python -m serenity.manage db-check` с её адресом.

Для аварийного восстановления остановите бот, восстановите резервную копию,
проверьте схему и подключение, затем запустите совместимую версию приложения.
Автоматических обратных миграций нет. Откат к старому приложению не использует
новые заявки и очередь задач; без проверки совместимости такой откат небезопасен.

Логи идут в стандартный вывод Railway с временем и именем модуля.
Токен и URI базы маскируются. При сбое сначала проверьте логи запуска,
доступность PostgreSQL, права Discord и наличие настроенных каналов/ролей.
